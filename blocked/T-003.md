# T-003: GitHub 上での診断実測待ち

2026-09-08 に `gh workflow run session0-diagnostic.yml --ref chore/two-pc-preparation` を実行したところ、
`HTTP 404: workflow session0-diagnostic.yml not found on the default branch` で終了した。

作業ブランチの 2156d47 は push 済みだが、main は 8b91020 のまま。
GitHub の登録済み workflow は CI、CodeQL、Release の 3 件で、診断 workflow は含まれていない。
[Draft PR #4](https://github.com/SioKo-Shox3/Sembazuru/pull/4) に診断差分を含めている。

T-007 で診断を workflow_call 対応にし、登録済み Release から同じコミットを呼ぶ定義を追加した。
このため、診断専用 workflow を先に main に登録する必要はない。
根拠は [GitHub の再利用可能 workflow の仕様](https://docs.github.com/en/actions/how-tos/reuse-automations/reuse-workflows)。同じリポジトリの相対パス参照は呼び出し元と同じコミットを使う。

修正を含む作業ブランチは 29a13f1 として push 済みで、ローカル・追跡ブランチ・リモートが一致している。
残る再開条件は `gh workflow run release.yml --ref chore/two-pc-preparation` を実行し、対象 SHA が一致することを確認すること。
2026-09-17 の実行は自動承認の分類器が Create Public Surface として拒否したため、ユーザーの明示指示が要る。
診断 job はブランチ指定の手動実行時だけ動く。パッケージ job と独立し、contents: read で secrets を継承しない。
パッケージ job も同時に実行され、署名 secret が設定済みなら既存の署名処理も走る。ブランチ ref では Release の公開ステップを実行しない。
最初に診断 job 自体が run に存在することも確認する。
GitHub hosted runner で A/B の flags、Job UI、分類、cleanup、worker の前後一致を測定する。
契約テスト 7 件の成功は SCM 実測の代わりにはならない。
このターンでは push、PR マージ、Release 公開を行っていない。ローカル SCM による代替実行も行っていない。
