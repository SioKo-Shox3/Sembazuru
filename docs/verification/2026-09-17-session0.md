## 結果: CREATE_NO_WINDOW は原因ではない

分類は **`NO_WINDOW_NOT_SUFFICIENT`**。両アームとも子プロセスが `0xc0000142` で終了した。

| | baseline | variant |
|---|---|---|
| CreationFlags | `0x00080404` | `0x08080404` (+ `CREATE_NO_WINDOW`) |
| Job UI | `0x000000fe` | `0x000000fe` |
| SpawnSucceeded | True | True |
| ChildExit | `0xc0000142` | `0xc0000142` |
| SpawnError / Stdout / Stderr | 空 | 空 |

事前に定めた判定規則（baseline 0142 かつ variant 0 のときだけ `NO_WINDOW_CAUSAL`）に照らし、
**製品の起動フラグに `CREATE_NO_WINDOW` を追加しない。** 追加しても直らないことが実測で示された。

## 実測から読み取れる真因

同じレコードに、子プロセスが起動に失敗する理由が出ている。

```
Station=Service-0x0-27fb60$  Desktop=Default
StationAccess=mask=0x0000006e; allowed=false; gle=5
DesktopAccess=mask=0x000000cf; allowed=false; gle=5
Broker=user=S-1-5-80-1970768882-...; integrity=12288
Action=user=S-1-5-80-1970768882-...; integrity=8192
StationDacl=... sid=S-1-5-80-1970768882-... , sid=S-1-5-32-544
DesktopDacl=... sid=S-1-5-80-1970768882-... , sid=S-1-5-32-544
```

- アクションのトークンは **Medium 整合性 (8192)**。`crates/worker/src/sandbox.rs:510` の
  `lower_to_medium_if_needed` が `CreateRestrictedToken` の後に設定する。
- ブローカー（ワーカーサービス）は **12288**。
- ウィンドウステーションとデスクトップの DACL は、サービス SID と `S-1-5-32-544`（Administrators）にしか
  許可を与えていない。制限付き・低整合性のアクショントークン向けのエントリはない。
- その結果、ステーションとデスクトップの両方で `allowed=false; gle=5`（アクセス拒否）。

ウィンドウステーションとデスクトップを開けないプロセスは初期化に失敗し、`0xC0000142`
(`STATUS_DLL_INIT_FAILED`) で終了する。`CREATE_NO_WINDOW` はこの接続自体を止めないので効かない。

## この実測が置き換える前提

- 「installed worker の 0xC0000142 は起動フラグで直る」という作業前提は**否定された**。
- CI の `m9_installer_acl.ps1:1332` が `--no-vfs` の plain control で失敗するのも同じ原因で、
  フック DLL は関与しない。
- T-006 で扱ったログオン単位のウィンドウステーション生成は、この問題の解の側にある。
  アクション専用のステーションとデスクトップを用意する設計が次の検討対象になる。
