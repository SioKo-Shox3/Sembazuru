# M9.6（改訂）作業計画 — admission 再編・自己更新撤回・参加モード

別セッションで実装するための **作業計画＋方針資料**。方針はリード承認済み（2026-06-19）。
実装セッションはまず Plan Mode に入り、本書と関連コードをサブエージェントで把握し、
ADR を確定してから着手すること（いきなりコードを書かない）。

## 経緯（なぜ改訂か）

M9.6 として ADR 0009（GUI 自己更新）と ADR 0010（CPU 連動 admission）を実装したが、議論の結果:

- **自己更新（ADR 0009）は撤回**。理由: (1) 更新は GitHub からの手動 DL でよい（Incredibuild も手動）、
  (2) 分散ビルドでは各ノードが勝手に版を上げると **version skew → 決定性/キャッシュ整合の崩れ**を招くため、
  むしろ「クラスタを 1 版に揃える」方が正しい、(3) 自己更新を CI 署名で守っても完全乗っ取りには無力で、
  実 OV cert のコストに見合わない（→署名は任意降格）。
- 代わりに **「サーバー版基準の版ゲート」（ADR 0011）** と **「worker 参加モード」（ADR 0012）** を採用。

## 確定方針（リード承認 2026-06-19）

1. **自己更新を撤回**。アプリ内バージョンアップ案内なし。更新は手動（GitHub Releases から MSI を DL して入れ直す）。
2. **版整合**: サーバー役＝**agent/daemon（コーディネータ）** の版を基準に、`worker.version` が **完全一致**しない
   worker を**ビルド参加（スケジューリング）から除外**。除外方式は **「登録は維持・スケジューリング除外・
   ダッシュボードに理由表示」**（拒否ではなく可視化）。
3. **worker 参加モード**（ADR 0010 の一般化）: `always`／`adaptive`(既定)／`off` の 3 モード。
   - `always` = 負荷を見ず静的 capacity まで常時参加（idle_cpu OFF 相当）。
   - `adaptive` = idle CPU としきい値で実効容量を動的調整（現 ADR 0010 の既定 ON＝良き隣人）。
   - `off` = 実効 0＝スケジューリング除外（登録維持・ダッシュボード「不参加」表示）。
   - しきい値は当面 **idle CPU のみ**（reserve/hysteresis/ema は実装済み、`participation_floor_pct` を明示ノブ化）。
     memory/在席/時間帯などの他信号は **将来拡張の枠だけ**設け、今は作り込まない（スコープ膨張回避）。
4. **署名/実 OV cert は任意降格**。機能を gate するものではない（自己更新が消えたため）。当面未署名で可
   （手動 DL は SmartScreen クリックで運用）。**release pipeline は「手動配布用の MSI 発行」として保持**。
5. **非交渉**: No UBA（UBA は設計の参考のみ・コード非流用・clean-room）。決定性不変（本作業は admission/
   scheduling のみ＝成果物バイト不変）。ローカルフォールバック常時（全 worker 除外でも `run_local` で完走）。

## 統一 admission モデル（3 ADR が 1 箇所に合流）

worker がスケジューリング対象になる条件（scheduler の eligibility filter ＝ ADR 0010 で作った場所に重ねる）:

```
worker.version == agent.version   (ADR 0011)
  かつ participation_mode != off   (ADR 0012)
  かつ effective_capacity > 0      (ADR 0010: adaptive は CPU 連動 / always は静的 capacity)
```

除外時は理由（`version-mismatch` / `off` / `cpu-busy`）を `WorkerStatus` に載せダッシュボード表示。
**いずれもスケジューリングのみの変更＝出力バイト不変**（determinism harness で担保）。

## スコープ

### A. 自己更新（ADR 0009）の撤回

撤回する実装フットプリント（`git diff bb784aa..m9/self-update` で確定済み）:

- **削除**: `crates/gui/src/update/mod.rs`、`crates/gui/src/verify/mod.rs`、`crates/gui/src/app/updates.rs`。
- **revert**: `crates/gui/src/lib.rs`（`pub mod update; pub mod verify;` を除去）、
  `crates/gui/src/tray.rs`（`CheckForUpdates`）、`crates/gui/src/app/mod.rs`（updates 配線・起動時 check）、
  `crates/gui/src/svcctl/mod.rs`（`elevate_and_run` の一般化を元の `request_action` 専用形へ戻す）。
- **依存撤去**: `crates/gui/Cargo.toml` の `reqwest`/`semver`/`serde`、`windows-sys` の
  `Win32_Security_WinTrust`/`Win32_Security_Cryptography`（`Cargo.lock` 反映）。
  → **副次効果（良い）: GUI が loopback-only に戻り外向き通信ゼロ＝EDR 姿勢が単純化**。
- **docs**: `docs/security/edr-allowlist.md` の「Outbound network（自己更新）」開示を撤回し「外向きなし」へ戻す。
- **保持して転用**（削除しない）: `installer/check_version_sync.ps1`、`.github/workflows/release.yml`、
  `installer/sign_release.ps1`、`ci.yml` の version-sync ステップ ＝「タグ → (任意で署名) → GitHub Release に
  MSI 公開（**手動 DL 用**）」。release.yml/edr-allowlist 等の文面から自己更新前提の記述だけ外す。
- **ADR**: `docs/decisions/0009-app-self-update-github-releases.md` を **Superseded** 化
  （「手動更新＋版ゲート admission（0011）に置換」を末尾に追記。決定 2026-06-19）。

### B. ADR 0011 — 版ゲート admission（新規）

- **ADR 起案 → ACCEPTED**（本書の方針を `docs/decisions/0011-version-gated-admission.md` に成文化）。
- **proto**（`crates/proto/proto/sembazuru/v0/control.proto`）: worker の app build 版を非破壊追加。
  `Capabilities`（または `RegisterRequest`）に `optional string worker_version`、GUI 表示用に
  `WorkerStatus` にも `optional string worker_version`。※ §6「capability flag でゲート・版で sniff しない」は
  **wire 互換の話**であり、本ゲートは別レイヤ（admission/scheduling の決定性安全）である旨を proto コメントに明記。
- **worker**（`crates/worker/src/coordination.rs::local_capabilities`）: `env!("CARGO_PKG_VERSION")` を載せる。
- **agent**（`crates/agent/src/coordination.rs` / `scheduler.rs`）: 自身の `env!("CARGO_PKG_VERSION")` と比較し、
  完全一致しない worker をスケジューリング eligibility から除外（`WorkerEntry` に version を保持、ADR 0010 の
  filter に重ねる）。除外理由を保持。
- **gui**: ダッシュボードに worker 版＋「version-mismatch＝除外」を表示。
- **Done-when**: 版不一致 worker が選ばれない UT、全 worker 不一致でも `run_local` 完走、版一致は従来どおり、
  determinism 緑、fmt/clippy/test 緑。

### C. ADR 0012 — worker 参加モード（新規・ADR 0010 の一般化）

- **ADR 起案 → ACCEPTED**（`docs/decisions/0012-worker-participation-modes.md`）。
- **config**（`crates/worker/src/config.rs`）: 既存 `idle_cpu_enabled: bool` を **参加モード**に置換。
  `participation_mode: always | adaptive | off`（TOML 文字列、既定 `adaptive`）＋
  `adaptive` 用しきい値（`reserve_pct`/`hysteresis_pct`/`ema_alpha_pct` は流用、`participation_floor_pct` 追加）。
  `SEMBAZURU_PARTICIPATION_MODE` 等の env override。既存 `IdleCpuSettings` を内包する `ParticipationSettings` に。
- **worker**（`cpu_monitor.rs` / `coordination.rs`）: モードに応じて報告値を決める。
  `always`→capacity 相当を常時報告／`adaptive`→現行 CPU 連動／`off`→不参加シグナル（実効 0 を明示）。
- **proto/agent**: worker が現在のモード/参加可否を heartbeat か Status に載せ、agent の eligibility（mode≠off）と
  ダッシュボード表示に反映。
- **拡張枠**: 状態信号を CPU 以外（memory/在席/時間帯）に増やせる構造にするが、**今は CPU のみ実装**。
- **Done-when**: `off` worker が除外され `run_local` 完走、`always` worker が負荷無関係に capacity 提供、
  `adaptive` が従来 ADR 0010 挙動、しきい値 env/TOML が効く UT、determinism 緑、fmt/clippy/test 緑。

## ブランチ戦略（実装セッションが選択。推奨は方式1）

未 push（push はリード）。`main` 直 push 不可（分類器）。

- **方式1（推奨・安全）**: 現 `m9/finalize`（ADR 0010 実装＋自己更新＋release pipeline を含む）から作業。
  自己更新を **surgical に撤回する 1 コミット**（A の削除/revert）を積み、続けて 0011/0012 を実装。
  release pipeline/docs/CI/`check_version_sync.ps1` は既に存在＝**再作成不要**。履歴に add→remove の churn が
  残るが、push 前にリードが squash 可能。
- **方式2（履歴クリーン）**: `m9/installer`（base、bb784aa）から新 `m9/admission` を切り、`m9/cpu-admission`
  （ADR 0010）をマージ、自己更新は取り込まず、保持物（release.yml/sign_release.ps1/check_version_sync.ps1/
  ci version-sync/docs）を cherry-pick 再投入してから 0011/0012。自己更新が履歴に残らない代わりに再投入の手間。

いずれも最終的に `m9/finalize`（または新 admission ブランチ）= **自己更新なし・ADR 0010/0011/0012 あり・
release pipeline は手動配布用** の状態にする。
